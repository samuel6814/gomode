================================================================================
                        GOMODE — PRODUCTION DEPLOYMENT GUIDE
================================================================================
Architecture Overview:
  • Frontend: Vercel (React + Vite SPA)
  • Backend: Render (Node.js / Express API with Prisma ORM)
  • Database: Neon Serverless PostgreSQL
  • Reverse Proxy: Vercel `/api/(.*)` rewrites directly to Render backend,
    ensuring cookies are treated as first-party (same-origin) by all browsers.

================================================================================
PART 1: NEON POSTGRESQL DATABASE SETUP
================================================================================
1. Create a Neon Project:
   - Sign up or log in at https://console.neon.tech/
   - Create a new project: "gomode-db"
   - Select the region closest to your Render server (e.g., Frankfurt or US East).

2. Retrieve Connection Strings:
   - Copy the "Pooled connection" string (uses PgBouncer, ideal for serverless):
     postgresql://<user>:<password>@<endpoint>-pooler.<region>.aws.neon.tech/<dbname>?sslmode=require
   - Copy the "Direct connection" string (for running migrations):
     postgresql://<user>:<password>@<endpoint>.<region>.aws.neon.tech/<dbname>?sslmode=require

3. Push Database Schema:
   From your local terminal in the project root:
     cd server
     # Set DATABASE_URL in server/.env with your direct connection string:
     # DATABASE_URL="postgresql://<user>:<password>@<endpoint>.<region>.aws.neon.tech/<dbname>?sslmode=require"
     npx prisma db push

4. Seed the GoMode Apparel Catalog & Admin Account:
   Run the seeding script to populate the 15 apparel products, categories, delivery fees, and admin user:
     node scripts/seedGomodeCatalog.js

   Default Admin Account:
     Email:    admin@gomode.com
     Password: Admin1234!

PART 2: BACKEND DEPLOYMENT ON RENDER
================================================================================
1. Create a Web Service:
   - Log in to https://dashboard.render.com/
   - Click "New +" -> "Web Service"
   - Connect your GitHub repository: `sneakers-garden`

2. Configure Build & Runtime:
   - Name:             sneaker-garden-api (or your chosen name)
   - Region:           Choose same region as Neon DB (e.g., Frankfurt / US East)
   - Branch:           main (or master)
   - Root Directory:   server
   - Runtime:          Node
   - Build Command:    npm install && npx prisma generate
   - Start Command:    node index.js
   - Plan:             Starter or Free

3. Set Environment Variables on Render:
   In the "Environment" tab of your service, add the following key-value pairs:
     NODE_ENV              = production
     PORT                  = 5000
     DATABASE_URL          = <Your Neon Pooled Connection String with ?sslmode=require>
     DIRECT_URL            = <Your Neon Direct Connection String with ?sslmode=require>
     JWT_SECRET            = <Generate a strong 32+ character random secret string>
     BETTER_AUTH_SECRET    = <Generate a strong 32+ character random secret string>
     BETTER_AUTH_URL       = https://gomode-api.onrender.com
     CLIENT_URL            = https://gomode.vercel.app
     
   (Optional - Cloudinary for image uploads in admin):
     CLOUDINARY_CLOUD_NAME = <your_cloudinary_cloud_name>
     CLOUDINARY_API_KEY    = <your_cloudinary_api_key>
     CLOUDINARY_API_SECRET = <your_cloudinary_api_secret>

4. Deploy & Verify:
   - Click "Create Web Service".
   - Monitor the deploy logs until you see: "Server running on port 5000".
   - Test health check by visiting in browser:
     https://gomode-api.onrender.com/api/products
     (Should return JSON with the seeded apparel products).

PART 3: FRONTEND DEPLOYMENT ON VERCEL & REVERSE PROXY
================================================================================
1. Configure `client/vercel.json`:
   Open `client/vercel.json` and ensure the destination points to your live Render API URL:
   {
     "rewrites": [
       {
         "source": "/api/(.*)",
         "destination": "https://gomode-api.onrender.com/api/$1"
       },
       {
         "source": "/(.*)",
         "destination": "/index.html"
       }
     ]
   }

2. Import Project on Vercel:
   - Log in to https://vercel.com/
   - Click "Add New..." -> "Project"
   - Select your GitHub repository: `gomode`

3. Configure Project Settings:
   - Framework Preset: Vite
   - Root Directory:   Edit and set to `client`
   - Build Command:    npm run build
   - Output Directory: dist
   - Install Command:  npm install

4. Set Environment Variables on Vercel:
     VITE_SITE_URL = https://gomode.vercel.app
     # Note: No VITE_API_URL is required because client/src/api/apiBase.js
     # defaults to the relative '/api' endpoint, perfectly routed by vercel.json.

5. Deploy:
   - Click "Deploy".
   - Vercel will build and assign your domain: `https://gomode.vercel.app`.

================================================================================
PART 4: WHY THE REVERSE PROXY ELIMINATES CROSS-DOMAIN COOKIE BLOCKING
================================================================================
Problem in Cross-Origin Architecture:
  When the frontend is on Vercel (https://gomode.vercel.app) and the backend is on
  Render (https://gomode-api.onrender.com), modern browsers (Safari ITP, Chrome, Brave)
  classify authentication cookies as 3rd-party cross-site cookies and block them.

The Solution (Configured in client/vercel.json):
  1. The browser sends all API and Auth requests to:
     `https://gomode.vercel.app/api/auth/...`
  2. Vercel's edge network proxies the request to:
     `https://gomode-api.onrender.com/api/auth/...`
  3. Because the browser communicates only with `gomode.vercel.app`, the cookies
     are treated as 1st-party (same-origin).
  4. Authentication cookies (`sameSite: 'lax'`, `secure: true`, `httpOnly: true`) are
     stored and sent reliably across all devices and browsers.

PART 6: CRON JOBS SETUP (KEEP-ALIVE & DASHBOARD METRICS)
================================================================================
Render Free Web Services spin down to sleep after 15 minutes of inactivity.
Setting up a cron ping keeps the backend awake 24/7 so visitors never experience
cold-start loading delays.

1. Automated GitHub Actions Keep-Alive Cron (Built-in to Repository):
   - Workflow File:   .github/workflows/keepalive.yml
   - Schedule:        Every 10 minutes (cron: `*/10 * * * *`)
   - Target URL:      https://gomode-api.onrender.com/api/healthz
   - How it works:    Runs automatically on GitHub Actions in the samuel6814/gomode
                      repository once pushed. No 3rd-party account required!

2. External Keep-Alive Cron (cron-job.org or UptimeRobot):
   - Service:         https://cron-job.org (100% Free) or https://uptimerobot.com
   - Title:           GoMode API Keep-Alive
   - URL:             https://gomode-api.onrender.com/api/healthz
                      (or: https://gomode-api.onrender.com/health)
   - HTTP Method:     GET
   - Schedule:        Every 10 minutes (cron: `*/10 * * * *`)
   - Notice:          The `/api/healthz` endpoint is specifically placed BEFORE
                      the API rate limiter in server/index.js, ensuring it never
                      gets blocked or rate-limited.

3. Dashboard Metrics Precomputation Cron (Render Native):
   - Included in:     render.yaml (`gomode-stats-cron`)
   - Manual Setup:    On Render Dashboard: Click "New +" -> "Cron Job"
   - Name:            gomode-stats-cron
   - Root Directory:  server
   - Command:         node cron/run.js (or: `npm run cron:stats`)
   - Schedule:        Every 10 minutes (`*/10 * * * *`)
   - Environment:     Same DATABASE_URL as the main web service.

4. Local / Manual CLI Cron Runners:
   - In server directory:
     - `npm run cron:keepalive` -> Pings https://gomode-api.onrender.com/api/healthz
     - `npm run cron:stats`     -> Computes and caches dashboard revenue & order metrics
